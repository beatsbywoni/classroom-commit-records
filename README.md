# GitHub Classroom commit records before and after generative AI: replication package

This package accompanies a manuscript under double-anonymous review about what must be verified before commit records of public GitHub Classroom repositories are read as traces of students' work (the title and citation will be added on publication). It contains the collection and analysis scripts, the derived tables with hashed identifiers, the result file of every analysis, the LaTeX source of the submitted manuscript, the preregistered protocol and the results of the registered analysis as the registered scripts produced them, and the results of the intermediate analyses that the manuscript's Appendix B describes. What can be re-run from these files, and what cannot, is set out under "Reproducing the results from this package".

## Large files

Three compressed tables are stored in parts of 9 MB so that every file can be uploaded through the GitHub web interface: `data_derived/commits_v2_hashed.csv.gz`, `data_derived/commit_history_flags_hashed.csv.gz`, and `data_derived/v4/commit_features_v4_hashed.csv.gz`. Reassemble each before use and check it against `SHA256SUMS_large_files.txt` in the same folder:

```
cd data_derived && for f in commits_v2_hashed.csv.gz commit_history_flags_hashed.csv.gz; do cat $f.part* > $f; done && sha256sum -c SHA256SUMS_large_files.txt
cd v4 && cat commit_features_v4_hashed.csv.gz.part* > commit_features_v4_hashed.csv.gz && sha256sum -c SHA256SUMS_large_files.txt
```

## Reproducing the results from this package

`scripts/00_reproduce_from_package.py` works from the files in this package only and never writes into it. In a new folder it builds the layout the scripts were written for (`scripts/` next to `data/v2/`): it reassembles the tables stored in parts and checks their SHA-256 sums, writes the hashed derived tables under the names the scripts expect (renaming `repo_hash`, `org_hash`, and `sha_hash` to `repo`, `org`, and `sha`; the hashes preserve every equality the analysis uses, and rows keep their original order, so random draws are reproduced), and copies the distributed result files. It then runs the steps below, compares what they produce with what the package distributes, writes `reproduction_report.json`, and exits with status 1 if any comparison fails.

```
python scripts/00_reproduce_from_package.py --work /path/to/new/folder                         # A and C below, about 2 minutes
python scripts/00_reproduce_from_package.py --work /path/to/new/folder --parts era,agent        # also re-fits two parts (B)
python scripts/00_reproduce_from_package.py --work /path/to/new/folder --parts all --jobs 2     # re-fits every part (B), several hours
```

Environment: Python 3.10 or later with numpy, pandas, scipy, statsmodels, and matplotlib; the test below used Python 3.13 with numpy 2.5, pandas 3.0, scipy 1.18, statsmodels 0.15, and matplotlib 3.11 (`pip install numpy pandas scipy statsmodels matplotlib`). Output: the work folder holds `out/tables5/`, `out/figs/`, `refit/` (re-fitted result files), `logs/`, `manuscript_check.json`, and `reproduction_report.json`.

Comparisons and tolerances. Generated tables (`out/tables5/*.tex`, including `results_macros.tex`) must be identical to `manuscript/tables5/`. Re-fitted result files and the standardized results are compared number by number with the distributed ones: relative tolerance 1e-6 (absolute for numbers below 1) by default; 1e-5 for REML variance components and log-likelihoods (`sigma2_u`, `sigma2`, `llf`), which the optimizer determines less precisely than the coefficients; and an absolute 1/2000 for wild-bootstrap p-values (`p_wild`), which count 1,999 replicates and can move by one replicate when ties among bootstrap statistics break differently because floating-point sums are accumulated in a different order. Numbers within a tolerance but not identical are counted separately in the report. The figure data (`figure_data.json`) are compared in the same way. The tables, figures, and text numbers are always built from the distributed result files, so that a re-fit does not change what they are compared with.

Tests of this version (October 30, 2026; test 1 repeated on October 31, 2026, for v1.2.1, with the same results), each on a copy of the package in a new folder, in the environment above with two cores:

1. Without `--parts` (steps A and C; about one minute; exit status 0): the 15 generated table and text-macro files were identical to `manuscript/tables5/`; the 496 numbers plotted in Figures 1 to 4 were identical to `manuscript/figs/figure_data.json`; the 23 standardized result files (9,385 numbers) agreed with the distributed ones (174 within tolerance but not identical, none outside), and the 224 deterministic checks of `37_common_sd.py` passed; `40_check_manuscript.py` found all 100 expected phrases and no unclassified number.
2. With `--parts` (step B), all 16 analysis parts and the 7 attribution-rule variants were re-fitted from the hashed derived tables in four invocations, each in a new folder (1: `era`, `agent`, `era_regime`, `agent_nostarter`; 2: `era_preswitch`, `era_prebeta`, `stability`, `extra`, `year`, `low_msg`, `within_wide`; 3: `samples_ge5`, `samples_test_orgs_kept`, `samples_copies_kept`, `samples_tierAB` and the 7 rule variants; 4: `samples_full_frame_ge3`, about 30 minutes alone). Of the 9,494 numbers compared (2,350, 2,222, 4,520, and 402), none differed beyond the tolerances and 2,598 differed within them. Three wild-bootstrap p-values moved by one replicate in 2,000 (`era.within.large_insert_share_200`, .2695 against the distributed .269; `era.within.time_dispersion`, .9405 against .940; `agent.within.time_dispersion`, .408 against .4085), because ties among absolute bootstrap statistics break differently when floating-point sums are accumulated in a different order; built from these re-fitted files, Tables 10 and 11 would print .270, .941, and .409 or .408 in place of the submitted values. Apart from p-values, the largest relative deviation was 1.1e-6, in one organization variance. The re-fitted `era` and `agent` files also record 28 grid fields of the within-organization test inversion that the distributed files, written by an earlier version of that function, do not contain; these fields are not compared. The first invocation (`era`, `agent`, `era_regime`, `agent_nostarter`) used a pre-release revision of the entry point whose re-fit and comparison code is the same as in this version except that the p-value tolerance lacked an allowance of 1e-12 for floating-point representation; its files were compared again with this version's code.

## Identifiers and privacy

Repository names, organization names and commit SHAs are replaced by salted SHA-256 hashes (16 hex characters; one salt for all three, so that a SHA shared by two repositories of one organization is still detectable as shared). Author identities were hashed at scan time with a different salt, and the identity matching of the activity rule stores only whether a match occurred. Neither salt is distributed. Commit messages are not distributed. Raw `git log` output for the 58,516 repositories and the manual-review file (which contains commit subject lines) are not distributed because they contain names, e-mail addresses and free text; they are available to reviewers and editors on request under access control.

## Pipeline of the reported analysis

1. `01_pilot_count.sh` … `03_clone_extract.sh`: enumerate the frame through the GitHub Search API (which excludes forks unless asked) and clone each repository bare, extracting `git log --all --numstat`. Requires a GitHub token and network access; outputs are the raw logs (not distributed).
2. `11_extract_commits_v2.py`, `10_sample_v2.py`: commit-level table and sampling-frame flags.
3. `23_flags_v4.py`: one pass over the raw logs computing, for every non-bot commit in verified repositories, timing relative to repository creation, SHA sharing, owner match and author activity, and the outcome of the adopted activity rule and its variants; repository record with assignment-copy detection (`commit_features`, `repo_record`, `arcs_*`).
4. `12_signals_v2.py` with `FLAGS_FILE`, `ARCS_FILE`, `RECORD_FILE` and `OUT_NAME`: repository-level signals under each rule (`signals_v4`, `signals_rule_*`).
5. `22_activity_audit.py`, `29_activity_review_v4.py`: checks of the activity rules against timing and identity; stratified review sample and, given the judged file, stratum and weighted rates (`results_activity_validation.json`, `results_activity_review_v4.json`).
6. `33_starter_code.py`: root commits by the Classroom bot (starter code). `28_record_generation.py`: verified repositories by creation half-year, assignment copies, starter-code share, observation time. `34_verify_copies.py`: records the check of the assignment-copy name rule on sampled repositories against their public pages (number of forks; generated from a template); the pages were read in a browser session, and the script documents the samples and stores the result.
7. `25_analysis_v4.py` (run part by part with `PART=...`, or all parts with `run_v4_parts.sh`): all comparisons, using `reml_ri.py` for random-intercept models; contribution-capped estimates with organization-bootstrap intervals; within-organization comparisons with restricted wild cluster bootstrap and test inversion; year effects; low-commit repositories; thresholds; samples; rule variants (`MODE=rules`); stability.
8. `26_validate_reml.py`: the REML implementation against statsmodels (Nelder–Mead, BFGS, L-BFGS).
9. `27_trailer_v4.py`: AI and human-co-author trailer model.
10. `37_common_sd.py`: re-expresses every standardized estimate of a contrast in one unit (the SD of the signal in the primary sample of the contrast), recomputing and checking the deterministic coefficients; writes `results_v5_*.json`.
11. `38_text_numbers.py`: writes `results_macros.tex`, one LaTeX macro per result number cited in the text, from the result files. `35_tables_v5.py` and `36_figs_v5.py`: every generated table and the four figures of the submitted manuscript from the result files (no refitting). `40_check_manuscript.py`: checks the numbers typed into the manuscript source. `30_figs_v4.py` and `31_tables_v4.py` produced the figures and tables of an earlier draft.
12. `39_staff_review_estimates.py`: design-based estimates for the staff-like category of the commit review (needs the access-controlled review file; its output is distributed).
13. `32_build_package_v4.py`: assembles this layer of the package (hashing identifiers).

The scripts are provided in the form that was run on the unhashed data; `00_reproduce_from_package.py` (above) builds the layout and column names they expect from the hashed tables. Two steps need information that hashing removes and are reproducible only from the raw logs: owner matching (which compares author identifiers with the repository name) and assignment-copy detection (which reads the repository name); their outputs are distributed as columns.
